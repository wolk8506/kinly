# Управление дизайн-токенами

Используй этот навык при настройке темы приложения или добавлении новых цветов и стилей.

## Правила

1. Храни все базовые значения в одном месте (например, `styles/tokens.css` или `theme.ts`).
2. Разделяй токены на два уровня:
   * **Примитивы:** `--gray-900`, `--blue-500`, `--radius-md`.
   * **Семантические:** `--bg-surface`, `--text-muted`, `--accent-primary`, `--border-subtle`.
3. При добавлении любого нового цвета сразу прописывай его пару для темной темы (`[data-theme="dark"]` или `.dark`).
4. Запрещено использовать произвольные цвета напрямую в компонентах — только ссылки на семантические токены.

## Genealogy React — куда класть значения

В этом репозитории вместо `tokens.css` / отдельного `theme.ts` действуют такие источники (не дублируй числа в нескольких местах):

| Область | Код | Индекс / паттерн |
|--------|-----|------------------|
| MUI-тема, палитра, `glass.*`, светлая/тёмная | `src/theme/palette.js`, `src/theme/ThemeContext.js` | `docs/design/tokens.md` (surfaces) |
| App bar glass capsule (единственный источник чисел) | `src/layout/toolbarTokens.js` → `toolbarStyles.js` | `docs/design/tokens.md`, `docs/design/patterns.md` § App bar |
| Кнопки in-page / диалогов | `src/components/appButtonStyles.js`, `DialogActionButton.jsx` | `docs/design/tokens.md`, `components.md` |
| Примитивы UI | `@mui/material` theme + существующие экспорты темы | Не выдумывай radii/размеры кнопок в чате — из токенов или Figma (см. `AGENTS.md`) |

Тема переключается через контекст приложения (MUI `palette.mode`), не через произвольный `[data-theme]` в CSS — пары light/dark задавай в `palette.js` или в объектах, которые уже ветвятся по `mode`.

## macOS / Apple (Genealogy)

Направление продукта: **Apple / iOS-like** на кросс-платформенном **Electron**-десктопе (см. `docs/design/README.md`). Референс визуала — [Figma macOS 27 Community — Copy](https://www.figma.com/design/iNTC5hH5Yfj3bC127fwSDo/macOS-27--Community---Copy---Copy-); **не выдумывай** radii, размеры кнопок и отступы в чате — сверяй с `docs/design/tokens.md` и уже существующим кодом. Крупные расхождения с текущими экранами — только после явного одобрения пользователя на визуальное изменение (`AGENTS.md`).

| Тема macOS / Apple | В Genealogy |
|--------------------|-------------|
| Vibrancy / frosted glass | `glass.*` в `src/theme/palette.js`, App bar — `TOOLBAR_CAPSULE` + `backdrop-filter` через `toolbarStyles.js` (`patterns.md` § App bar) |
| Системная типографика | MUI theme + системный шрифт из темы; не подменять произвольными web-font без задачи |
| Заголовок окна без отдельной полосы | App bar = title bar; зона drag между кластерами toolbar — не ломать при добавлении кнопок |
| Иконки | SF Symbol-стиль где уже принят в экране; новые иконки — в духе kit (тонкие, 20px в toolbar hit), не «Material по умолчанию» без причины |
| Светлая и тёмная тема | Обе обязательны; на заметных правках glass/палитры — проверка в **обеих** темах |

**Сборка под Mac:** публичный и локальный `dist:mac` — **arm64 (Apple Silicon)**; Intel не целим. После заметных правок токенов/стекла имеет смысл smoke на macOS; агент скриншоты не делает — попросить пользователя приложить кадр при сомнениях.

Windows/Linux: те же семантические токены и тема; отличия только нативного chrome (меню Alt, установщик) — не плодить отдельные цвета «только для macOS», если нет бага платформы.

## Перед правками документации

Редактирование `docs/design/**` и согласование с Figma — только после явного «да» пользователю («Обновляем правила/документацию?»). Код токенов можно править по задаче; `tokens.md` — после подтверждения, если меняются зафиксированные числа или индекс.

## Чеклист агента

1. Найти существующий семантический токен или примитив в `palette.js` / `toolbarTokens.js` / `appButtonStyles.js`.
2. Добавить значение для **обеих** тем, если это цвет, граница или тень.
3. В компоненте — `theme.palette…`, `toolbarIconColor`, `TOOLBAR_*`, `sx` из общих стилей; не сырые `#hex` и не «магические» px без записи в источнике токенов.
4. App bar: только glass capsule (`ToolbarButtonGroup`, `patterns.md`); иконки в hit — `inherit`, не `primary` на toolbar.
5. После визуально заметных изменений — напомнить про скриншот/проверку в обеих темах; CHANGELOG — по правилам проекта (один bullet на фичу в unreleased).
